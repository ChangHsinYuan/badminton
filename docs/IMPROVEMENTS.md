## 球场标定原理与失效判据

### 不是"解方程", 是"模型匹配 + 假设枚举"

单应矩阵 8 个自由度, 靠线段本身解方程是不够的 (`court_fit.py`)。真实机制:

1. 白线 mask → 霍夫变换提线段 → 共线合并成**无限长直线参数** (a,b,c)
   ——线段残缺不影响整条直线的估计
2. 按方向分两族 (边线族/端线族, 对应场地两个正交方向)
3. **枚举对应假设**: 每族取 2 条得 4 个交点, 配上标线已知坐标值组合
   (边线 x∈{0, 0.46, 3.05, 5.64, 6.1}, 端线 y∈{0, 0.76, 4.72, 6.7, 8.68, 12.64, 13.4}),
   每组对应关系用 2×2 交点 DLT 解出一个候选 H——**不需要知道哪条检测线是
   哪条模型线**, 全部组合枚举出来让分数说话
4. 评分选优: 双向倒角 (模型线投影要贴白线 + 白线要被投影线解释) +
   **场地坐标系一致性** (检测线映回场地坐标系后必须是常量 x 或常量 y,
   且值接近某条模型线) → 最优假设 Nelder-Mead 8-DOF 精修 + 子集 ICP 扩展对应

"两根线"的直觉: 每族 2 条线给 4 个交点 = 8 个约束, 恰好钉死 8 DOF——这是
最低配置; 实际十几条线参与评分, 鲁棒性来自冗余。

### 不完整的线是常态, 三重容忍

- 霍夫直线参数是整条的, 缺一段不影响估计
- 评分逐线逐采样点计算, 缺失段自动跳过 (只降分不崩)
- 远端线在低视角下常只剩一小段: "子集 ICP" 以紧匹配线作基底、宽松候选
  逐子集试拼, 防止坏线拖垮全量 DLT

### 什么情况不能 (失效判据)

- **硬失败** (明确报错"未找到有效的单应性假设"): 某族线不足 2 条
  (如画面里只有一条网线); 两族线近于平行 (交点在图像外被过滤)
- **软失败** (有解但别信): 总分显著偏低; `per_line` 逐线支持度 BAD 且集中在
  远端 (提示镜头畸变——单应假设针孔+平面, 桶形畸变会让远端线系统性偏);
  相邻场地线混入 mask 导致错误吸附 (coverage<1, 白点映出场地外)
- **最终判据**: 人工看 `fit_overlay.jpg` 投影线是否压线
- **镜像歧义**: 羽毛球场所有标线关于中线 x=3.05 对称 (含网线), 存在左右
  镜像解且评分完全相同, 线本身无法消歧——叠加图上两种解都"贴合"。影响仅限
  站位左/右区标签互换; 速度/距网/变向率/持拍手投票 (用图像坐标) 不受影响。
  可消歧线索: 发球站位规则、比分牌、或人工在 overlay 上确认一次

## 击球类型可信度: 球轨迹缺失的影响

球检测的漏检是当前**最弱环节**, 且引入系统性偏差:

- **机制上的缓解**: 弧段 <4 点 (MIN_PTS) 或 <0.12s 不分类, 宁可"未识别"不硬猜;
  分类阈值从严 (杀球要求顶位<0.25 且凸比<0.13 且下坠峰>600px/s, 保精度弃召回)
- **系统性偏差**: YOLO 对慢速高空弧检出最好 (球大/轨迹长/无遮挡), 快球
  (杀/平抽) 受运动模糊+帧间大位移影响检出差, 网前小球常被身体遮挡。
  报告里"82~84% 高远球/挑球"应读作"**检出弧段中**的分布", 不是真实击球
  分布——慢球容易被检出本身就是选择偏差, 杀球被系统性漏计 (两个验证视频
  都是 ~83% 高远, 恰是嫌疑信号)
- **缺失对特征的具体伤害**: 凸比/顶点位置需要弧顶可见——球在最高点最快最易
  被丢帧, 弧顶一丢, "高远凸比>0.30"判据失效, 掉进未识别或误判吊球
- **使用建议**: 击球分布看两人相对趋势 (谁更爱上网), 别信绝对占比;
  杀球计数只当代码下限
- **改进方向**: TrackNetV3 提检出率、短缺口插值 (不可跨击球点, 会把两弧
  并一弧)、分类型检出率先验去偏、**手部挥拍轨迹融合** (手腕检出率远高于球
  且连续, 最有潜力的替代信号)

## 2D 边界与伪 3D 路线

当前处理分两层——一层是正确的 2D, 一层是妥协的 2D:

- **球员的 2D 是正确模型**: 脚踩地面, 地面单应变换数学上无损, 米制速度
  (m/s)、距离、站位都是真物理量
- **球的 2D 是妥协**: 只有图像 (u,v) 与像素速度, **高度信息完全缺失**。
  这正是删除拍击伸展指标的根本原因 (离地 1m 的手腕按地面点投影, 中位偏差
  10m+); 也是击球分类只用图像几何特征 (凸比/顶位/像素速度)、阈值绑定
  "低视角 720p/30fps" 标定的原因——换机位严格说要重新校阈值
- **设计边界**: 图像弧特征做**离散分类** (这是哪种球) 够用; 做**物理量**
  (球速 m/s、弧顶高度) 不行。管线自觉停在分类
- **伪 3D 路线**: 单目低视角无相机内参, 严格 3D 做不了, 但网高 1.55m 是
  已知量——网顶点同时落在地面平面与 1.55m 高度平面上, 双平面单应组合可解
  垂直方向灭点, 把球的高度与深度解耦, 恢复"球在场上空多高多远"。
  真 3D 需双目或多机位

## v1: AI 教练分析 (2026-11-14)

**新增模块**: `style_features.py` / `keyframes.py` / `style_coach.py`

从 `detections.jsonl` 提取跑位/步法/节奏特征, 抽取关键时刻帧(冲刺/挥拍/球接触)画骨架,
由 LLM 生成五节分析报告(球风画像/跑位步法/职业风格相似度/训练建议/关键帧点评)。

**踩坑记录**:

1. **深度分区坐标翻转 (严重)**: 初版把 y=0 当网前, 实际 y=0 是远端底线、y=6.7 才是网。
   导致报告把底线型球员误判为"网前蜘蛛", 整个叙事方向相反。
   修复: 统一用 `dist_from_net()` (到网距离) 计算深度分区, upper 用 `6.7-y`, lower 用 `y-6.7`。
   **教训: 涉及"前后场"语义的统计必须先声明坐标系约定, 并用基准位置做交叉自检
   (热区分布均值应与基准位置一致)。**
2. **双重变换 bug**: 分区函数内部已做坐标换算, 调用处又传入了换算后的值, 分区结果全错。
3. **rtmpose 低置信关键点污染**: 手部关键点置信度低时输出 (0,0), 污染伸展/变向统计,
   需过滤后计算。
4. **推理型模型输出污染**: glm-5.3-flash 的思考过程混入正文且 max_tokens 内被截断,
   文本分析默认改用 qwen3.8-chat, `--model` 可覆盖。

## v2.1: 击球类型识别 (2026-11-16)

**新增模块**: `shot_types.py` — 球轨迹分段 + 规则分类(杀球/吊球/高远/平抽)。

### 方法

1. 检测点按帧间隙切 run → 按"击球后强力上升"主判据 + "速度突跳"兜底判定击球边界并合并
2. 对每条弧线计算: 时长/凸弦比/顶点位置/峰值下坠速度/均速/峰值二维速度 (全部图像空间)
3. 规则分类; 落点区用**下一拍击球者的站位**标注(地面真值), 完全绕开空中球地面投影不可信的问题

### 校准过程 (低视角 720p/30fps 林丹杯实测)

| 轮次 | 问题 | 修复 |
|---|---|---|
| 1 | 稠密网格插值跨大间隙拼接出大量假弧线, 假速度达 54 万 px/s | 弃用插值, 改 run 合并, 速度只用真实相邻帧差 |
| 2 | mapper 导入路径错误 (`court.mapper` → 实际 `badminton_analysis.court.mapper`) 落点全空 | 修正导入; 单应性对空中球的地面投影必然飞出场外, 改用接球者站位 |
| 3 | 落速符号搞反(图像 y 向下), 平抽/杀球全错 | 统一"下坠速度正值"约定 |
| 4 | 视觉 API 标注 24 条样本比对: 一致率仅 19%, 暴露静止段混入(均速 5px/s 的捡球等待)、平抽时长门限过紧 | 静止段过滤 ms<60; 平抽 dur<1.5; 吊球凸比区间放宽; 峰值取次大值抗单帧抖动 |
| 5 | 碎片化: 任意符号翻转都断开弧线 | 击球主判据改为"出射侧强力上升"(入射侧速度可以小, 击球瞬间垂直速度本来就趋零) |

### 已知限制 (如实告知使用者)

- **覆盖率有限**: 45% 球检出率下, 90 秒回合约识别 19 次有效出手(估计总击球 64 次),
  分布仅作参考; 提示词已声明"不要对单次击球下断言"
- **深度-高度混叠**: 单目图像空间的垂直运动混合了深度运动(球飞向镜头在画面里也"下坠"),
  这是单目低视角的固有精度天花板; 彻底解决需 3D 球轨迹或双目
- **归属透视偏差**: 近端球员同样物理距离对应更大像素距离, 归属距离门槛放宽到 420px;
  报告输出"轮转交替率"作为归属质量 QA 指标(单打理想 ~90%+, 本视频实测 45%, 归属噪声较大)

## v2.2: 职业风格特征卡匹配 (2026-11-16)

**新增模块**: `pro_profiles.py` + `profiles/` 特征卡库。

### 动机

v1 的"职业风格相似度"由 LLM 凭训练记忆联想, 不可复现。实测案例: 林丹杯视频近端球员
实际是桃田贤斗本人, LLM 却把他比作安赛龙, 把远端业余球员比作桃田——**完全张冠李戴**。

### 方法

- 特征卡 = 归一化特征向量(四项风格指数 + 三区站位占比 + 速度/冲刺/变向 + 击球类型分布)
- 相似度 = 加权 L2 距离(权重见 `pro_profiles.SPEC`), 缺失特征自动跳过并重归一
- `--build` 从任意视频生成实测卡; `--match` 与库内所有卡计算最近邻
- LLM 只负责**解读计算结果**(为何相似/差异在哪), 不再自行发明对照

### 验证

用本视频构建桃田贤斗特征卡后重新匹配: 近端球员 → 桃田卡 **100%** 自匹配, 交叉匹配 86%,
区分度良好。LLM 解读时还自动完成了"变向率 0.06 次/秒"的翻案: v1 报告将其列为近端球员
短板, v2 报告结合桃田身份正确解读为"步法极其流畅、缺乏剧烈变向, 恰是技术高明的体现"。

### 注意
- 已有两张卡(`source=measured`)来自本视频实测, 属于自匹配平凡解; 跨视频对比才有意义
- 内置 6 张球星风格画像卡(林丹/李宗伟/谌龙/安赛龙/金廷/安东森, `source=curated`):
  参数为公开球风资料(维基百科打法描述 + LLM 知识交叉核对)的**估计值**, 数量级对本管线
  特征尺度做了校准, 但并非从球星比赛视频实测; 仅作风格倾向对照, 不参与精确断言
- 实测验证: 本视频两人最接近的球星卡是谌龙(80%, 防守反击型), 与慢节奏高远为主的
  实测特征一致; 爆发进攻型(金廷/安赛龙/林丹)排位靠后, 区分度符合预期

## 持拍手误判修复 (2026-11-16)

**问题**: v1 报告把两名球员都判成"右手", 实际近端球员是左手持拍(用户看视频确认)。

**原因** (两层):
1. 原启发式"哪只手腕被检出的帧数多"与持拍手无关——检出率差异来自遮挡和置信度
   (实测近端左/右腕检出 1647/2351 帧, 但近端持拍的是左手)
2. 首版修复用的"全视频球离双手最近的 Top-K 帧"投票也会出错: 球从身体旁**飞掠而过**
   的非击球帧会投出假票(近端最近 5 帧全是右腕近, 但那些是球路过, 不是击球)

**修复** (`style_features.infer_hand_pref`):
- 主信号改为 **shot_types 归属后的击球帧投票**: 每次出手在 frame0-4~frame0+1 窗口内
  取双手距球最近的一帧投一票(窗口内球必属本次交锋, 不设近距离门限——frame0 时球
  常已飞出 200~400px); 击球票 <5 次才退回全视频近帧 Top-K(带 180px 门限)
- 仅双手关键点同帧可见才计票, 避免单侧遮挡偏票; ≥60% 多数且 ≥3 票才下结论
- 报告标注票数: `持拍手: 左手 (近球投票 左10:右5)`
- 结果: 远端右手(4:20), 近端左手(10:5), 与人工核对一致
- 身份佐证: 近端球员 `--player-hint lower=桃田贤斗` — 桃田本人即左手持拍
  (英文维基百科 handedness: Left), 持拍手判定与身份、用户观察三方一致

**顺带修复**: 拍击伸展指标 (`reach_mean_m`) 发现是噪声——手腕离地 1m+, 地面单应投影
会把它打到远后方(中位偏差 10m+), 旧值来自每年几十个侥幸落进 0.3~2.5m 门槛的野值;
而图像空间距离乘地面深度比例尺在低视角下又会把"高度位移"按"深度比例"放大(均值被
截断顶死)。没有相机内参修不准, **删除该指标**, 诚实优于假精度。

在**陌生的第二段视频**上复现全流程, 验证 fork 核心卖点与 v2 特征卡:

**素材**: 武汉林丹杯 16 进 8 桃田贤斗 vs 王轶凡, 网后场边低视角, 9000 帧片段

官方"高清录播"多为转播多机位不可用, 固定低视角的 UP 主投稿才是目标素材)

**自动标定复现**: `fit_court_driver.py` 得分 0.796 (旧视频同级), 蓝线完美压线,
绿线小偏但可用于坐标换算——"任意场边低机位视频可用"不依赖调参

**跨视频身份识别 (风格指纹)**: 新视频近端球员对旧视频实测的 `桃田贤斗(measured)`
卡相似度 **96.1%**——这是第一次非自匹配的身份验证: 同一位球员(桃田)出现在两个
不同机位的视频里, 风格指纹把他认了出来 (变向率 0.12 vs 0.125 次/秒、中场控制型
等特征一致)。球员身份即由风格匹配定义, 不再依赖看清画面。

**持拍手继承机制**: 新视频近球投票把近端(桃田, 左手将)误判成右手 (左12:右22),
而同一套代码在旧视频上是对的——近球投票信号**依赖相机几何, 跨机位不稳**(伸展
投票同样反转)。修复: 特征卡 `--build` 时保存 `hand_pref`; 报告生成时若某侧
对实测卡匹配 ≥90%, 持拍手**继承卡片记录**并在摘要标注来源与本地票数:
`持拍手: 左手 (继承自匹配卡 桃田贤斗; 本场近球投票 左12:右22)`
——同一名球员的持拍手不会变, 高置信身份匹配下卡片比单场投票可信。
继承值与本地投票一致时显示保持原样(旧视频输出不受影响)。

## 方法论原则 (2026-11-16)

贯穿 v1~v2.2 的四条设计原则:

1. **计算与解读分离**: LLM 从不做任何计算。所有数字 (风格指数/相似度/票数) 由
   确定性代码算好, 以"计算结果块"注入提示词并要求"只解读不发明"——堵住 LLM
   分析工具最大的病: 编数据。
2. **风格即身份**: 低视角下人脸/球衣不可读 (视觉模型实测连蒙带猜), 改用运动
   统计特征做球员身份证——同一套身体换机位风格不变, 是比外观更本质的特征。
   身份由特征卡最近邻定义 (桃田卡跨视频 96.1%), 不依赖看清画面。
3. **证据链可追溯 + 诚实优先**: 每个结论带来源 (`继承自匹配卡 X; 本场投票 a:b`);
   噪声指标直接删除 (拍击伸展) 而非硬修; curated 卡标注来源且不参与精确断言;
   自匹配 100% 是平凡解不算验证, 跨视频才算。
4. **信号可信度分层**: 多信号冗余 + 明确失效模式。持拍手为例: 近球投票依赖
   相机几何 (同代码换机位翻车), 故建立继承链——高置信身份匹配的卡片记录 >
   单场投票 (人不会换持拍手, 投票会随机位翻转)。

## v3: 单目 3D 测量链 (2026-11-18)

三步从 2D 视频恢复米制物理量, 全部只用场地线自标定, 无需标定物:

1. **相机自标定** (`camera_selfcalib.py`): 球场单应矩阵 inv(H) 分解出 K/R/t
   (主点居中 + 方形像素假设, 双方程解 f 取均值)。**左手系陷阱**: canonicalize()
   的镜像规范化使 H 系为左手系, 需按相机高度 C_z>0 自动选朝向类, 否则相机会
   被解到地面之下; 下游 3D 点须换算 y_w = 13.4 − y_hn。两视频独立标定的相机
   位置差 <12cm, 网顶(1.55m)投影 vs 网带实测误差 ±1~7px。
2. **击球点高度** (`hit_points3d.py`): 球射线 × 击球者脚位竖直线最近逼近。
   高远球击球点中位 2.2~2.4m, 上手/下手差 0.8~1.0m ≈ 臂长+拍, 量纲自洽。
3. **物理弹道拟合** (`trajectory3d.py`): 重力+二次阻力 RK4, 深度网格初值+两级
   精修; 接收者强锚点 (球到末端必减速至 ~7m/s, 必落在对手 1.5m 内) + 击球者
   弱锚点, 破单目"慢近/快远"速度-深度简并。β 收敛到 0.19~0.21 (物理真值
   ≈0.22, 羽球终端速度 6.7m/s), 新视频 119 弧 0 失败, 最快 238km/h (反推仅
   0.05s = 首检即接触, 高可信), 高远出手中位 24.2m/s, 过网余量 +0.4~+0.9m。

**验证逻辑**: 阻力系数 β 是全链路的物理级试金石——标定、锚点、时间轴任何一环
出错, β 都不会停在 0.2 附近; 它收敛即整链可信。`visualize3d.py` 把弹道画回
视频 (黄=可信, 灰+??=低置信) 供肉眼验收, README 顶部即演示样片。

**已知边界**: 快球首检出滞后于实际击球 → 出手速度用物理反推 (`speed_at_owner_
axis`), t_back>0.3s 不可信 (json 存 t_back 供过滤); 检测漏检 (运动模糊/遮挡)
决定覆盖率上限——已画弹道的弧都是真实检测点拟合, 插值只补几何空隙。

## 已知限制与后续方向

1. **球检测**: TrackNetV3 (32ch 输入) 可提升检出率与精度 → 直接改善击球类型覆盖率
2. **3D 球轨迹**: 已由 v3 单目 3D 测量链实现 (自标定+锚点拟合, 见上文); 剩余: 远端
   风格卡在 3D 链上的专一性验证、更多机位泛化、帧率提升 (30fps 限死时间精度)
3. **特征卡库扩充**: 对公开职业比赛视频批量 `--build`, 建立跨球员可比的特征库
4. **击球类型**: 引入手部挥拍轨迹(已有 hands 数据)与球轨迹联合分类, 替代纯球轨迹规则
5. **变向率指标**: 对"省力型"步法系统性低估, 报告需结合身份/风格解读, 不宜单独当短板
6. **球检出偏差 → 击球分布有偏**: 详见上文[击球类型可信度](#击球类型可信度-球轨迹缺失的影响)
7. **球的米制量受检测精度约束**: v3 已突破"纯 2D 无物理量"的边界, 但球速/击球点
   精度仍受检出噪声制约 (见 v3 已知边界)
8. **标定左右镜像歧义**: 详见上文[球场标定原理与失效判据](#球场标定原理与失效判据)
